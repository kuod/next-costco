# Next Costco

Static GitHub Pages site that ranks the 50 US places most ripe for a new Costco warehouse. Users can reweight the scoring factors with sliders and see the ranking update live.

## Layout

- `index.html`: the whole site (inline CSS/JS, vanilla; Leaflet from cdnjs). No build step.
- `data/rankings.json`: generated by the pipeline. Contains all 339 scored candidate places (with 0-100 component scores), default weights, and warehouse coordinates. The browser re-scores from `components`, so the weights in `scripts/build.py` and the JS must stay in step.
- `scripts/fetch_acs.py`: downloads ACS 5-year place data per state from Census Reporter (keyless) into `raw/acs/`.
- `scripts/build.py`: joins ACS + Census gazetteers + CBSA delineation + OSM Costco locations, scores places, writes `data/rankings.json`.
- `raw/`: downloaded inputs, gitignored. Re-create them to rebuild (see below).

## Rebuilding data

Inputs in `raw/`: `costco_osm.json` (Overpass export, `brand:wikidata=Q715583` in the US), `geo/2024_Gaz_place_national.txt`, `geo/2024_Gaz_counties_national.txt`, `geo/list1_2023.xlsx` (CBSA delineation), and `acs/*.json` from `fetch_acs.py`.
`build.py` needs `openpyxl` (use a venv; system Python has none). Run `python3 scripts/fetch_acs.py` then `python3 scripts/build.py`.

## Scoring (keep in sync between `build.py` and `index.html`)

Seven components, each 0-100: `gap` (distance to nearest warehouse), `catch` (underserved people within 10 mi), `income`, `edu` (bachelor's+), `density` (suburban sweet spot), `metro` (people per warehouse in the metro), `own` (homeownership). Default weights: 25/20/20/10/10/10/5.
Candidates: pop >= 40k and nearest warehouse >= 8 mi. The top 50 are chosen greedily with a 20-mile minimum spacing; `index.html` repeats this logic in `compute()`. Verified that default weights reproduce the build's top 50 exactly; re-check after changing either side (the build ranks on the unrounded score, and components are stored to 2 decimals).

## Known data caveats

- Warehouse locations come from OpenStreetMap and can lag new openings. Spot-check picks against costco.com.
- Places whose water area is more than twice their land area are excluded (their Census centroids fall in water; San Francisco was the case that exposed this).
- Place-to-metro assignment uses the nearest county centroid within the state, so a few places near county lines may land in the wrong metro.
- Distances are straight-line from the Census internal point, not drive time.

## Working notes

- Preview locally: `python3 -m http.server` in the repo root, then open http://localhost:8000 (the page fetches `data/rankings.json`, so `file://` won't work).
- Deployed from the `main` branch root via GitHub Pages.
- Syntax-check the inline script after edits: extract it and run `node --check`.
